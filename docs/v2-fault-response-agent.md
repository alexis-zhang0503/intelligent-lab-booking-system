# V2.1 故障处置 Agent

管理员的故障处置页面围绕一个明确边界工作：系统可以分析影响并给出
替代设备建议，但不会自动取消、迁移或创建学生预约。

## 流程

1. 管理员在未关闭故障上选择“分析影响”。
2. 数据库仅查询未来、未开始的 `reserved` 和 `confirmed` 预约，并为每条
   预约找出同一时段至多三台可用且不冲突的替代设备。
3. 管理员填写隔离原因并确认。系统将设备标记为 `faulty`，保留原预约，
   并写入隔离审计事件。
4. 维修完成后，管理员填写维修说明。系统恢复设备可预约、关闭故障，并
   写入修复审计事件。

## 权限与审计

- 影响分析、隔离、修复和复发指标都要求 `public.is_admin()`。
- 浏览器不直接更新 `devices` 或 `issue_reports` 来完成处置。
- `fault_response_events` 是只追加的审计记录；学生无读取权限。
- “自动改约”在本版本固定为 `false`。若未来新增学生授权策略，也必须在
  每次写入时再次执行预约冲突校验。
